# Why3 obligations for the DOP853 synthesis slice

This directory holds the machine-checked part of the Fortran Synthesis pilot
(lazy-fortran/fortnum issue #62). The derivation half of the pilot (the
DOP853 tableau) is complete; this is the verification half.

`dop853_tableau.mlw` is generated by `gen_dop853_model.py` from the exact
Q(sqrt 6) values recorded beside every coefficient of
`src/generated/fortnum_dop853_tableau.f90`. `r6` is an uninterpreted real
with `r6 * r6 = 6`, so each goal is an exact identity in Q(sqrt 6). The 40
goals are:

- explicitness: `a(i,j) = 0` for `j >= i` (12 goals);
- stage consistency: `sum_j a(i,j) = c(i)` for every stage (12 goals);
- the bushy-tree order conditions `sum_i b_i c_i^(k-1) = 1/k`, `k = 1..8`;
- the error estimators annihilate low-degree polynomials:
  `sum_i e5_i c_i^(k-1) = 0` for `k = 1..5` and
  `sum_i e3_i c_i^(k-1) = 0` for `k = 1..3`.

The remaining order-8 conditions (all 200 rooted trees) are checked
numerically in `test/ode/test_fortnum_dop853_order_conditions.f90`. The
driver's step preconditions (`h > 0`, array extents) are guarded in
`src/ode/fortnum_ode_dop853.f90` and are not modelled here.

## Discharge

The Why3 toolchain and an SMT prover are not part of the default build or of
CI. To discharge:

```sh
./discharge.sh
```

The script first checks that the committed theory matches the committed
tableau, then runs `why3 prove -P <prover> -t 60 dop853_tableau.mlw` for each
available prover and fails unless every goal is Valid. With Why3 1.8.2,
Z3 and cvc5 each report all 40 goals Valid; changing one right-hand side
(`row_sum3` or `weight_moment8`) makes the prover report `Unknown (sat)`.

## Why exact mathematics is not the whole story

The identities hold over the exact Q(sqrt 6) values of the derived tableau.
The Fortran code uses correctly rounded doubles of those values, and exact
mathematics cannot prove floating-point behavior. That split is intentional:
proofs replace what is provable, and numerical tests
(`test_fortnum_dop853_order_conditions`, `test_fortnum_ode_dop853`,
`test_fortnum_dop853_oracle`) retain what is not.
